# Frontier Atlas Bridge

Модуль Foundry VTT v14 (проверен на 14.360): мост между хабом Frontier Atlas и сценой Foundry. Только для мастера, игроки модуль не видят.

- **Хаб → Foundry.** Карта игроков (только разведанное и открытое) становится фоном сцены; заметки — записями журнала (секрет — на скрытой странице), таблицы — RollTable. С модулем `great-route-hex-crawl` 0.3.0+ ещё настраиваются зоны по местностям и ссылки гексов на журнал. Повторное получение **обновляет на месте**: жетоны, стены, рисунки и состояние гекскраула не трогаются.
- **Foundry → хаб.** Гексы, которые гекскраул пометил как `discovered` / `visited` / `cleared`, уходят в хаб как разведанные (только открывают). После отправки фон сцены перерисовывается.

## Установка

Скопируйте папку модуля в `Data/modules/frontier-atlas-bridge` или подключите junction (из `cmd`):

```
mklink /J "%LOCALAPPDATA%\FoundryVTT\Data\modules\frontier-atlas-bridge" "D:\ClaudeFun\frontier-atlas-bridge"
```

Включите модуль в мире. Зоны и разведка требуют `great-route-hex-crawl` версии **0.3.0 и новее** (методы API `createStorage` и `updateConfig`); без него или со старой версией мост делает сцену, журнал и таблицы, а зоны пропускает с понятным сообщением.

## Использование

1. **Токен.** В хабе: страница кампании, панель Foundry, «Создать токен» (показывается один раз).
2. В Foundry на панели сцены (слева) откройте группу **Frontier Atlas** (иконка карты с меткой) → «Получить карту из хаба».
3. **Подключение:** адрес хаба (`https://atlas.koshkaslojkoy.com`; локально `http://localhost:3001`) и токен → «Проверить подключение». Рабочий сохранённый токен пропускает этот шаг.
4. **Карта:** выберите карту кампании (если открытая сцена уже связана, выбрана её карта).
5. **Предпросмотр:** четыре категории с галочками (таблицы, журнал, сцена, зоны), счётчики «создать / изменить / удалить / без изменений». Записи журнала, изменённые в Foundry, показаны отдельно («Изменено в Foundry») и **по умолчанию не перезаписываются**; галочка заменяет их версией хаба. «Применить» неактивна, пока нечего менять.
6. **Результат:** журнал действий, «Открыть сцену».
7. **Разведка:** инструмент «Отправить разведку в хаб» показывает список новых гексов; кнопка отправляет их и перерисовывает фон. Для этого сцена должна быть создана мостом и у неё должно быть хранилище гекскраула.

Цвет иконки группы: серая — сцена не связана или хаб ещё не проверен; зелёная — актуально; оранжевая — в хабе есть обновление; красная — ошибка (текст в подсказке). Хаб проверяется один раз при открытии связанной сцены (сравниваются `rev` и хэш фона, потому что разведка `rev` не меняет); при обновлении предлагается открыть предпросмотр, ничего не применяется само.

Смена размера карты, масштаба или сетки в хабе: существующая сцена **не меняется** — создаётся новая сцена (с зонами), связь переходит на неё; у старой снимаются флаги моста, она остаётся как есть. Журнал и таблицы общие и обновляются на месте.

Метки на сцене: у заметок, не открытых игрокам, текст — только номер гекса («14.08»); у открытых — «14.08 Название».

## Настройки

Отдельного меню нет, всё в окне моста (настройки `scope: client`, хранятся в браузере мастера):

- адрес хаба;
- токен — по одному на мир, «Забыть токен» удаляет;
- **автоотправка разведки** (по умолчанию выключена) — переключатель внизу окна. Когда гекскраул записывает состояние в хранилище привязанной сцены (прибытие экспедиции), новые гексы без предпросмотра уходят в хаб и фон перерисовывается. Условие — токен и включённая настройка в этом клиенте; отправка идемпотентна, поэтому дубли двух мастеров безвредны.

## Совместимость

- Foundry VTT 14.360 (`minimum` и `verified`).
- Карты хаба с `doc.version = 1`; другая версия — понятная ошибка «обновите модуль».
- `great-route-hex-crawl` 0.3.0+ (необязательный, `recommends`).
- Системы: любые (модуль не зависит от системы).
- Общий код хаба лежит копией в `vendor/atlas.mjs`; пересборка в репозитории хаба: `npm run build:bridge-vendor` (конфиг `tools/bridge-vendor/`, путь к мосту — `BRIDGE_DIR`, по умолчанию соседняя папка). Правки отрисовки в хабе доходят до моста только после пересборки и повышения версии модуля (версия входит в хэш фона, поэтому фон перерисуется).
- Проверка чистой логики: `node --test "tests/*.test.mjs"` (ключи клеток сверяются с настоящим `HexagonalGrid`, если исходники Foundry лежат в `E:/Foundry VTT v14/resources/app` или в `FOUNDRY_APP`).

## Ограничения

- **Скрытие интерфейсом — не защита.** Скрытая страница секрета (`ownership NONE`), журналы с `ownership NONE` и метки без названия скрыты средствами интерфейса Foundry; игрок с DevTools или прямым доступом к данным мира может их увидеть. Не храните в журналах моста того, что игрок не должен узнать ни при каких условиях.
- Журналы создаются невидимыми для игроков: открывайте их сами. Повторное получение не меняет выданные вами права (кроме страницы секрета, она всегда скрыта).
- **Старые PNG не удаляются.** Имя файла содержит хэш карты игроков (`worlds/<мир>/frontier-atlas/<карта>-<хэш>.png`); клиент Foundry не умеет удалять файлы, поэтому лишние файлы чистите вручную.
- **Лимит конфига гекскраула.** Конфиг не может превышать 2 МБ (лимит импорта гекскраула). Если зоны и ссылки не помещаются, предпросмотр сообщает об этом и зоны отключаются.
- Зоны `fa-terrain-*` принадлежат мосту: их клетки перерисовываются по местностям хаба. Привязки, название и приоритет, которые вы настроили, не трогаются; привязки новой зоны берутся из `terrainTables` хаба только при её создании. Исчезнувшая в хабе местность оставляет пустую зону. Чужие зоны не затрагиваются. Ссылку гекса на журнал, поставленную вами, мост не перезаписывает.
- Оранжевая кнопка держится, пока записи, изменённые в Foundry (конфликты), не заменены версией хаба.
- Изменения зон идут через очередь прибытия гекскраула; сериализация с прибытием гарантирована только на клиенте активного мастера (окно предупреждает, если вы не он).
- Таблицы изменения в Foundry не отслеживают (правьте их в хабе); `gm.notes[].tables` к гексам не привязываются.
- Хаб по `http://` недоступен из Foundry, открытого по `https://` (блокировка смешанного содержимого браузером).
- Токен хранится открытым текстом в localStorage браузера мастера.
